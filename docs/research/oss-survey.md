# OSS-библиотеки для Android-приложения «просмотр и редактирование документов»

Дата проверки: **25.10.2026**. Всё, что помечено «факт», измерено/прочитано в этот день (GitHub API, Maven Central,
Google Maven, `maven.ghostscript.com`, F-Droid, содержимое APK/AAR). Оценки помечены явно.

## 0. Метод и базовая линия по весу

Проверялись: страница репозитория (лицензия, `pushed_at`, `archived`), последний релиз/версия на Maven, реальный размер
артефакта и `.so` внутри него, наличие LICENSE-файла.

Базовая линия — два APK, лежащих в проекте:

| APK | Размер на диске | Что внутри (замер) |
|---|---|---|
| `com.ncloudtech.cloudoffice.apk` | **273,0 MiB** (574 MiB распакованных) | `lib/` 96,9 MiB сжатыми; `libCloudOfficeJNIcore42.so` 138,05 MiB + `core41.so` 136,22 MiB, `libcoksn.so` 32,3 MiB, `libcompdf.so` 16,05 MiB; `assets/www.zip` 38,84 MiB; в dex — маркеры `collabora` (137) и `com.aspose.words` (8) |

## (б) Разбор по доменам

### 1. PDF

Матрица возможностей (что реально даёт движок):

| Движок | Рендер | Извлечение текста | AcroForm | Аннотации/факсимиле | Запись в файл |
|---|---|---|---|---|---|
| `androidx.pdf` / `PdfRenderer` | да | частично (зависит от версии платформы) | нет | нет | нет |
| pdfium (биндинг io.legere) | да | да | нет в биндинге | нет | нет |
| pdf.js | да | да | отрисовка полей | нет | нет |
| PDFBox-Android | растр (медленно) | да | **да** | **да** (штамп/картинка) | **да** |
| MuPDF | да | да | **да** | **да** | **да** |

**1.1 `androidx.pdf:pdf-viewer` — главная находка.** Официальный Jetpack-просмотрщик: `1.0.0-beta01` в Google Maven
(`dl.google.com/dl/android/maven2/androidx/pdf/pdf-viewer/`), AAR **1,23 MiB**, `classes.jar` 0,86 MiB, **нативных
библиотек нет** — работает поверх системного `PdfRenderer`. Даёт готовый экран просмотра с выделением текста, поиском
и ссылками (заявлено в AndroidX; проверено: артефакт существует, размер, отсутствие `.so`). Минусы: beta, только
просмотр, поведение зависит от системного рендера (на старых прошивках — артефакты и медленный первый рендер).

**1.2 pdfium.** Живой биндинг: `io.legere:pdfiumandroid` 1.0.20 (POM: `github.com/johngray1965/PdfiumAndroidKt`,
Apache-2.0, лицензия в самом репозитории GitHub не определяется — `NOASSERTION`, это надо поправить в своём NOTICE).
Замер AAR: **9,61 MiB**, внутри `libpdfium.so`: arm64-v8a **4,55**, x86_64 4,74, x86 4,32, armeabi-v7a 3,05 MiB,
плюс `libpdfiumandroid.so` 0,35 MiB. Для arm64-only сборки — **≈4,9 MiB**. Репозиторий живой (push 26.07.2026,
релизы 2.0.3 и 3.0.4-alpha01).

Про «мёртвый `barteksc/AndroidPdfViewer`»: **это уже не так**. Запрос к `barteksc/AndroidPdfViewer` редиректит на
**`DImuthuUpe/AndroidPdfViewer`** — Apache-2.0, 8 479★, push **07.11.2025**. Сам `barteksc/PdfiumAndroid` — 557★,
push 19.03.2024, лицензия не определяется. То есть живой форк есть, но новых версий pdfium он не приносит: pdfium
внутри старый, поэтому для нового проекта логичнее `io.legere`.

**1.3 MuPDF** (`ArtifexSoftware/mupdf`, AGPL-3.0, 3 021★, push 23.10.2026; `mupdf-android-viewer` — AGPL-3.0, 200★).
Единственный OSS-движок, который «из коробки» умеет и рендер, и формы, и аннотации, и подпись. Цена — **AGPL**:
для закрытого приложения нужна коммерческая лицензия Artifex. Вес: `com.artifex.mupdf:fitz:1.28.5` в
`maven.ghostscript.com` — AAR **20,6 MiB** на 4 ABI (≈5 MiB на ABI, оценка: пофайловый список получить не удалось,
хост отдавал 16 КБ за 200 с).

**1.4 PDFBox-Android** (`TomRoush/PdfBox-Android`, Apache-2.0, 1 195★). Единственный практичный способ **писать** в PDF:
заполнение AcroForm (`PDAcroForm`), штамп картинкой (`PDAnnotationRubberStamp`/`PDAnnotationWidget`) — то есть
факсимиле и подпись-картинка. AAR **3,10 MiB**, но POM тянет три артефакта BouncyCastle 1.72, из них `bcprov`
**8,91 MiB** — реальная цена ≈ **12 MiB**. Минус: последний релиз **02.01.2023**, push 18.03.2024; рендер медленный,
для экрана просмотра не годится.

**1.5 pdf.js** (`mozilla/pdf.js`, Apache-2.0, 54 041★, push 24.10.2026): 0,34 + 1,31 MiB в WebView — лучшая точность
вёрстки при нулевом нативном коде; минус — WebView, память, отсутствие записи.

### 2. Офисные форматы

**2.1 LibreOfficeKit — единственный настоящий OSS-офис.** `libreoffice/core`, `android/README.md` прямо описывает
архитектуру: ядро в одной библиотеке **`liblo-native-code.so`**, рендер тайлами через OpenGL ES 2, обмен с LOK по JNI
в отдельном потоке, **редактирование поддержано** (4 потока: UI, GL, LOKitThread, soffice). Это не «вьюер», это
полноценный движок.

Настоящий вес: APK **LibreOffice Viewer 25.8.7.3** из F-Droid (`org.documentfoundation.libreoffice`, versionCode 118)
— **74,0 MiB** (vc=117 88,1; vc=116 84,3). То есть «сотни мегабайт» — не обязательное свойство: 74 МБ хватает на
полный офисный вьюер. 273 МБ CloudOffice — это два ядра + Aspose + дублированные ICU + web-UI, а не неизбежность.

Минусы, которые надо принять: сборка NDK на часы и десятки ГБ, размер AAR-модуля, ARM-only, лицензионная
неоднозначность (см. §в), сложность обновления. Встраивание = тащить `android/` + `libreofficekit/` и собирать
`liblo-native-code.so` под свои ABI.

**Collabora Office для Android** — тот же LOK-движок в коммерческой упаковке (в референсном CloudOffice есть
`libcoksn.so` 32,3 MiB и строки `collabora` в dex — судя по именам, Collabora Online Kit). Открытого репозитория
самого приложения нет, поэтому как источник кода это не вариант; как доказательство, что LOK на Android работает
и редактирует — да.

**2.2 Apache POI / docx4j — это парсеры, не рендереры.** POI 5.5.1: `poi` 2,87 + `poi-ooxml` 1,96 + `xmlbeans` 2,11
= **6,9 MiB** jars. На Android требует `poi-on-android` (`centic9/poi-on-android`, Apache-2.0, push 02.10.2026) —
dex-лимиты, `javax.xml`-зависимости, медленный старт. Даёт текст/таблицы/стили, но **не даёт вёрстки страницы**.
docx4j 11.5.3 (релиз 07.05.2025, `docx4j-core` **3,51 MiB**) ещё тяжелее по зависимостям (JAXB), на Android
исторически проблемный; лицензия в GitHub не определена — проверять LICENSE перед использованием.

**2.3 «Парсим OOXML сами» — работает, и есть чем вдохновиться.** `mokshablr/gander` (MIT, 1 316★, push 24.10.2026,
minSdk 26, разрешений нет, INTERNET нет) — приложение ~5 МБ, которое открывает DOCX/XLSX/PPTX/ODT. Как именно:
`app/src/main/assets/viewer/docx.html` + `docx-preview.min.js`, `xlsx.full.min.js` (SheetJS), `pptx/pptxjs.js` +
`jszip2.min.js`, `pdf.min.mjs` для PDF. **Нативных библиотек в проекте нет вообще** — вся отрисовка в WebView, а
системный `PdfRenderer` вынесен в отдельный процесс через `IPdfRenderer.aidl` (для превью). Зависимости — только
`androidx.webkit`, media3, subsampling-scale-image-view.

Это ровно тот путь, который даёт «в разы меньше»: цена — WebView-рендеринг, ограниченная точность и то, что DOCX
показывается не идеально (а `.doc`/`.xls` вообще не входят). Свежий аналог: `MJrFusion/Docxion` (Apache-2.0, 6★,
push 17.09.2026) — Compose-обёртка над тем же подходом, но проект молодой и мало проверенный.

**2.4 `.doc`/`.xls` (бинарные).** OSS-пути два: POI `HWPF`/`HSSF` (текст и таблицы, без вёрстки; POI поддерживает
их до сих пор) либо LibreOffice. Лёгкого рендерера не существует — это надо честно принять.

**2.5 Итог по офису.** Промежуточного «маленького нативного рендерера OOXML» в природе нет. Реальные варианты:
(a) WebView + JS-конвертеры (5 МБ, вёрстка приблизительная), (b) LibreOfficeKit (74+ МБ, вёрстка настоящая),
(c) POI только для извлечения текста/таблиц и «плоского» просмотра.

### 4. Книги

**EPUB.** `io.documentnode:epub4j-core` 4.2.2 — Apache-2.0, **0,27 MiB**, релиз 05.12.2024, репо 50★, push 31.08.2026:

**MOBI/AZW3.** `bfabiszewski/libmobi` — **LGPL-3.0**, 487★, push 29.10.2024: C-библиотека, **готового Android-порта

push 24.10.2026): отдельные NDK-модули `:nativeLibs:mupdfModule` и `:nativeLibs:djvuModule`. Это самый дорогой
нишевый формат: тянет GPL на всё приложение и отдельную сборку NDK.

## (в) Лицензионные ловушки

1. **AGPL-3.0 (MuPDF, KOReader, Readest).** Публикация в Google Play разрешена, но AGPL требует предоставить
   исходники **всему**, кто взаимодействует с программой по сети (§13), а при распространении APK — весь
   corresponding source под AGPL. Для закрытого продукта это означает: либо открыть всё приложение, либо купить
   коммерческую лицензию (Artifex её продаёт — это и есть бизнес-модель MuPDF). «Спрятать» MuPDF в отдельном
   процессе/модуле нельзя: производная работа — всё приложение.
2. **GPL-3.0 (DjVuLibre, Orion Viewer, CoolReader, Librera).** Сильнее AGPL по факту: любое распространение APK
   обязывает отдать исходники всего приложения под GPL. Для Google Play это допустимо, для закрытого форка —
   нет. DjVuLibre именно поэтому «бесплатен только для GPL-приложений».
3. **LGPL-2.1 (sora-editor).** Динамическая линковка разрешена, но нужно: (а) уведомить, (б) дать возможность
   заменить библиотеку. На Android AAR вливается в dex, и «заменить» пользователь не может — юридически это серая
   зона, которую обычно закрывают модификацией LGPL-библиотеки в отдельный динамический модуль или отказом от неё.
   Для редактора Markdown проще взять Apache/MIT-альтернативу.
4. **LGPL-3.0 (libmobi).** Плюс anti-tivoization и требование Installation Information для «User Product» —
   на Android это дополнительная головная боль. Плюс JNI-обвязку придётся писать и сопровождать самим.
5. **MPL-2.0 vs `COPYING` (LibreOffice).** Файлы LibreOffice исторически под MPL-2.0 (файловый копилефт: закрытое
   приложение можно, но изменённые MPL-файлы надо опубликовать). При этом **в корне репозитория `COPYING` содержит
   текст GNU GPL v3**, и GitHub определяет лицензию репозитория как GPL-3.0. Это реальный конфликт, а не
   недоразумение: перед коммерческим использованием нужен аудит конкретных файлов, которые вы собираете, и
   юридическая консультация. Если планируется закрытый форк — это блокер, пока не доказано обратное.
6. **UnRAR freeware (junrar).** Не OSI-лицензия. Разрешает использовать исходники для распаковки, **запрещает**
   применять их для создания архиватора, совместимого с RAR, и запрещает релицензирование. В приложении нужен
   отдельный NOTICE, а совмещать с GPL-кодом нельзя.
7. **«Нет LICENSE-файла» (psiegman/epublib, docx4j в части GitHub-метаданных, PdfiumAndroidKt).** Отсутствие файла
   ≠ свобода использования: по умолчанию действует полный копирайт. Это отдельный риск-пункт в аудите.
8. **Apache-2.0 (PDFBox, POI, AndroidX, epub4j, pdf.js, SheetJS).** Безопасно, но требует сохранить LICENSE и
   NOTICE, а также обозначить изменения в файлах. Патентная оговорка — плюс.
9. **JS-компоненты в WebView.** SheetJS — Apache-2.0, PPTXjs — MIT, pdf.js — Apache-2.0, foliate-js — MIT.
   Их лицензии надо положить в `assets/licenses/` и показать в приложении: пользователь получает копию кода.
10. **Google Play.** Ни AGPL, ни GPL не запрещены политикой; запрещён **непредоставленный** исходник при
    copyleft. Практика: GPL/AGPL-приложения в Play живут, но их исходники публичны. Для закрытого продукта
    безопасный набор — Apache-2.0 / MIT / BSD / OFL.

## (г) Итоговые рекомендации

**Минимальный стек «просмотр всего» (оценка базового APK: 12–18 МБ):**

1. **PDF** — `androidx.pdf:pdf-viewer` (1,2 МБ, без `.so`), fallback — собственный экран на `PdfRenderer`.
   pdf.js (1,65 МБ assets) подключать только если нужна точная вёрстка сложных PDF.
2. **DOCX/XLSX/PPTX/ODT** — WebView + `docx-preview` + SheetJS + PPTXjs (подход gander), ODT конвертировать
   в HTML своим XSLT/парсером (ODT — это XML). Никакого нативного офиса в базовой сборке.
3. **Markdown** — `commonmark` 0,2 МБ + свой рендер; редактирование — `BasicTextField` с тулбаром.
4. **EPUB/FB2/MOBI/AZW3/CBZ** — WebView + **foliate-js** (MIT, ~0,3 МБ) закрывает всё сразу.
   Если нужен нативный EPUB-парсинг — `epub4j` 0,27 МБ.
5. **CBR** — `junrar` 0,15 МБ + текст лицензии UnRAR в NOTICE.
6. **Шрифты** — Noto Sans Regular + Bold (≈1,1 МБ), CJK не бандлить.
7. **DjVu** — вынести в отдельное решение: либо GPL-приложение/модуль на DjVuLibre (тогда весь продукт GPL),
   либо не поддерживать в первой версии. Это единственный формат, который ломает лицензионную чистоту.

**Опциональный модуль «редактирование офисных» (Play Feature Delivery, не в базовом APK):**

- **PDF-формы и факсимиле** — `pdfbox-android` (3,1 МБ + BouncyCastle 8,9 МБ). Единственный Apache-2.0-путь
  «поставить картинку-подпись и сохранить PDF».
- **Правка XLSX/DOCX на уровне данных** — POI (`poi-ooxml` + `xmlbeans`, 6,9 МБ) в динамическом модуле:
  ячейки, текст, стили. Вёрстку страницы это не сохраняет — обещать «как в Word» нельзя.
- **Настоящее офисное редактирование** — только LibreOfficeKit. Порог входа: +70 МБ, NDK-сборка, MPL/GPL-аудит,
  ARM-only. Если продукт должен быть «в разы меньше 270 МБ», это решение принимается один раз и до начала работы.

**Чего не существует (проверено, не искали дальше):**
- лёгкого нативного OSS-рендерера OOXML для Android (между «POI без вёрстки» и «LibreOffice на 74 МБ» ничего нет);
- Android-биндинга DjVuLibre или libmobi в Maven Central — только сборка NDK внутри приложения;
- поддерживаемого `AndroidPdfViewer` от barteksc — репозиторий переехал в `DImuthuUpe/AndroidPdfViewer`;
- androidx.pdf в стабильной версии — пока `1.0.0-beta01`;
- `TheirStory/ebook-reader` — такого репозитория нет (404); живого OSS-проекта с именем «BookReader» под Android
  в выдаче GitHub не нашлось, ближайшие аналоги — Anx Reader (MIT) и KOReader (AGPL).

## Приложение А. Воспроизводимость замеров

- Метаданные репозиториев/лицензии/даты — GitHub REST API (`/repos/{owner}/{repo}`), 25.10.2026.
- Версии и размеры — `repo1.maven.org`, `dl.google.com/dl/android/maven2`, `maven.ghostscript.com`
  (`com.artifex.mupdf:fitz:1.28.5`), размеры `.so` — распаковка AAR (`ZipFile`), литералы в тексте.
- LibreOffice Viewer — `f-droid.org/api/v1/packages/org.documentfoundation.libreoffice`, APK vc=118, `HEAD` → 74,0 MiB.
- Вес приложений — распаковка APK и подсчёт `lib/**/*.so` (`_scratch/apk_inventory.py`).
- Ограничение: в ходе работы исчерпалась квота GitHub API (60 запросов/час; сброс в ~11:03 локального времени),
  поэтому часть проверок сделана прямыми запросами к raw-файлам и Maven; размер релизного APK gander подтвердить
  не удалось (README заявляет ~5 МБ).
